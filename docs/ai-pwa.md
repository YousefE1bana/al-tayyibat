# AI resources and offline installation

The React application continues to use HashRouter on GitHub Pages. No SEO route infrastructure, notifications, accounts, analytics, backend or paid runtime service is introduced.

## Public AI resources

`llms.txt`, `data/foods.json`, `data/system-guide.json` and `ai/catalog-index.json` are generated by `npm run generate:assets` and automatically before every build. The catalog and guide use the same TypeScript data as the application. Generation has no timestamps, network calls or second hand-maintained catalog. Validation compares the committed files byte-for-byte with freshly computed output and enforces 385 foods and the reviewed status counts. Public fields are allowlisted; internal provenance notes and implementation paths are omitted. Notes already rendered in FoodDetails, including medical caveats, are retained as publicNotes.

llms.txt is an emerging convention. Its presence cannot guarantee that an AI system reads or follows it. Every full export includes an interpretation policy: attribute system claims, retain conditions and uncertainty, distinguish system claims from scientific evidence, and seek professional medical advice for medical decisions. The slim index points to the full catalog. Related foods and alternatives reference catalog IDs; images use public base-prefixed paths; interactive links retain hash routing.

## Approved icons

`public/brand/icon.png` remains the unchanged approved master. `scripts/generate-pwa-icons.ts` deterministically scales it into 192px and 512px PNGs, a 512px opaque maskable icon and a 180px Apple icon. The maskable artwork is contained within the central 80% safe-area circle. No tracing, redrawing or recoloring is performed. Tiny olive details remain limited at favicon sizes; the existing approved favicon is retained.

## Offline strategy

Vite PWA compiles the TypeScript worker using Workbox injectManifest. The manifest identity, start URL, scope and assets stay under `/al-tayyibat/`. Registration runs after window load in production builds only. The worker precaches the application shell, all route chunks, CSS, UI fonts, brand/icons, doctor portraits and AI exports. It never precaches the food image library. The postbuild check enforces a 5 MiB precache ceiling and writes a local, ignored size report under `output/pwa/`.

Same-origin food images use CacheFirst with a maximum of 60 entries, 30-day expiration and quota-error purging. Only successful HTTP 200 responses are cached. Expiration is enforced when that runtime cache is accessed; it is not a background timer. The existing SmartImage surface provides an accessible branded fallback for uncached images offline. No fabricated food image or data is substituted. After the first successful online visit and worker activation, search, categories, details, favorites, shopping and UI fonts work offline. LocalStorage remains the only persistence for user collections. Offline availability depends on browser storage remaining available; installation alone does not download every photo.

## Installation and updates

Chromium's deferred `beforeinstallprompt` event enables the unobtrusive footer action. Its native prompt is called only after a click. iOS/iPadOS users can explicitly open Safari Share → Add to Home Screen instructions; no automatic modal or repeated reminder is shown. Standalone display mode and `appinstalled` suppress installation controls.

The header, content gutters, footer and update notice respect safe-area insets on notched devices. iOS uses the standard status bar rather than placing controls behind a translucent bar.

Updates wait. A compact dismissible notice offers “تحديث الآن”; only accepting it posts SKIP_WAITING and reloads that page after controller change. Other open pages are not automatically reloaded. The browser checks the worker at registration and when the document becomes visible while online. Existing data remains on the device.

## Verification

Run typecheck, validate, build and qa:browser against a production preview. The worker has a separate WebWorker TypeScript configuration. Browser PWA QA uses real Chrome, real worker/cache lifecycle and offline network mode, with browser HTTP cache disabled. Local QA serves a second worker script revision to verify waiting/opt-in updates without publishing a fake release. Synthetic install events and standalone/iOS emulation cover UI branches; they do not claim to perform a native OS installation. Live QA checks real production manifest installability, scope, worker control, resources and offline behavior.

Requests intentionally failing for uncached offline food photos are expected; unexpected online resource failures, runtime errors, broken rendered images and accessibility violations are failures.
